DATA STATUS

What this frame can support

A complete export describes the export request. It does not prove a satellite observed every location or that clouds and smoke did not obscure the ground.

How the example heatmap is intended to work

In the live workflow, eligible MODIS and VIIRS active-fire records are mapped to a shared equal-area 1 km cell grid and deduplicated within sensor and UTC date. The 2D map smooths cell values with a fixed kernel. The relief view colors actual sample-cell footprints by those values. Sensor sources remain separate; “Both” is their distinct cell union. Missing records are not treated as no-fire observations.

This standalone mock does not run that science calculation. It uses invented values and procedural SVG shapes only to show the interface behavior.

△
Terrain relief

Real terrain is geographic context and elevation. It does not show active fire or fire behavior.

▧
Vegetation and land cover

NDVI and land-cover products have their own acquisition periods. They are not instantaneous fire-day measurements.

◉
Burn-date context

A later burned-area product can provide context, but it is not independent active-fire validation.

External designer brief · behavior and data contract

Purpose: redesign the historical replay interface for scientific users. Make choosing a case, reading the selected observation day, and understanding data completeness obvious. This file is the complete offline reference; no website, API, account, or dataset is needed to inspect it.

Data honesty: every count, time, coordinate, case label, map feature, and status in this mock is synthetic. Keep the “synthetic demo” warning prominent in any redesign. Do not turn heat into a simulated fire perimeter, forecast, or spread animation.

How the controls are meant to work

Named fire studySwitches case name, date window, mock AOI, day frames, heat clusters, counts, and sample records together.
Sensor viewShows both sources together or a single sensor. The “Both” total is a distinct shared-grid cell union, not MODIS + VIIRS added blindly.
Heatmap meaningDaily concentration, accumulated observed-day persistence through the selected date, or peak reported FRP in MW. The legend and explanatory copy change with the choice.
Context layerChanges the visual backdrop between terrain, vegetation NDVI, land cover, and burned-area context. Each needs a date/availability note in the real product.
Relief / flat viewChanges map presentation only. Relief uses a three-dimensional terrain surface in the real site; this offline example uses a restrained perspective treatment.
UTC day controlsSlider, date buttons, and play/pause all select the same frame. The map, selected date, source counts, sample table, and status cards update together.
Map inspectionClick a sample cell to preview cell detail. Fit-area and zoom controls demonstrate intended map actions; the SVG is only a static illustration.
ExportsButtons download a tiny CSV generated from the synthetic fixture so the affordance can be reviewed offline.

Assignment for the external UI designer

Use this file as the complete product brief and redesign the replay page into a clearer, more polished scientific workspace. Work from the visible mock and embedded code only; assume there is no access to the original website, APIs, credentials, or source datasets. Return a complete replacement HTML page that can be opened locally. Keep the page responsive and its controls usable.

  • You may reorganize the visual hierarchy, layout, typography, spacing, map frame, legend, and supporting details.
  • Keep case selection, sensor filtering, metric selection, context-layer selection, daily playback, day selection, map view, map inspection, and CSV export represented and understandable.
  • Keep every sample visibly synthetic. Do not add external imagery, remote fonts, APIs, or claims that the illustrative map is geographically accurate.
  • Preserve the scientific caveats: satellite detections are observations, completeness states are not fire/no-fire labels, and the heatmap is not a perimeter or forecast.
  • Make unknown, partial, and complete states distinguishable with text and shape as well as color; make the map usable with keyboard and assistive technology.

Design priorities

  • Keep the map as the main visual anchor, with controls and legend close to the map.
  • Use one continuous low-to-high heat ramp for magnitude. Use text and distinct symbols as well as color for MODIS and VIIRS.
  • Show the exact selected UTC date and completeness state next to the timeline.
  • Never make unknown or incomplete dates look like zero fire activity.
  • Keep sample counts separate by sensor and label their unit. Do not imply counts are burned area.
  • Retain a compact methodology/caveat section and a keyboard-accessible table alternative to map interaction.
  • Support wide desktop, tablet, and narrow mobile layouts. Respect reduced-motion preferences.

Local demo implementation

The editable fixture and UI behavior are in the final inline <script>. CSS, SVG terrain, controls, and interaction states are all in this single HTML file. It makes no network request. You may replace or reorganize the markup and visual system, but preserve truthful labels and the control behavior described above.
