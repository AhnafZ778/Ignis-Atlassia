File guide and limits

# One HTML file per page

Every main page is a complete, independent HTML file. CSS, JavaScript, fonts, icons, imagery, dummy API responses, design instructions, and reference screenshots are embedded in that same file. Copy one page anywhere and open it directly in a current browser. It needs no sidecar files, server, NASA account, key, or network connection. Navigation to another page requires that other HTML file beside it.

These are copies of the current website's layouts and renderers, populated with synthetic analytical values. Original controller sections and stylesheet order are labeled with data-source-file attributes for editing. The small handoff notice opens this embedded designer brief; hide it temporarily when taking a screenshot.

Default study: Northern California, July 2024. Atlas includes July dummy states for 2006–2025 and partial/unknown examples. Replay supports the supplied named cases, source/metric switches, timeline, and CSV downloads. Candidates and calendars remain selectable. Review includes 30 invented samples. Exposure has an embedded sample-mask download to demonstrate denominator cards. Other study requests may show an honest unavailable state.

All observation records, analytical results, masks, and service actions are design fixtures. Existing case names, explanatory copy, and landscape imagery remain visual context. Dummies never establish findings about a real fire. Import, sync, check, and evidence-export controls demonstrate UI states; they do not alter or validate a scientific archive.

The globe is an embedded capture of the existing page's appearance. Its surrounding UI remains interactive and editable, but its geographic camera and orbit are frozen in this offline reference. Replay keeps the original interactive 2D heatmap; the 3D action opens an embedded captured reference because real elevation streaming requires the live service. Preserve the actual globe, satellite/orbit layers, and terrain renderer during production integration. Map areas beyond the embedded extent are explicitly labeled.

The current Research overview's narrow-screen overflow is preserved as a design issue to fix. Production files were not changed by this handoff. Use the original application to integrate styling and structural changes; never promote the dummy adapter or frozen captures into its scientific data path.

The gzip block contains the complete local fixture library for this page. The small inline decoder opens it in memory. Use the brief's Download dummy responses button for an editable JSON view. All fonts and asset license notices are embedded below.

Master redesign prompt

# Master prompt for the external visual overhaul

You are redesigning the complete UI of **Ignis-Atlassia / FireAtlas**, a NASA Space Apps project centered on harmonizing MODIS and VIIRS hotspot observations. The product combines a globe-led introduction, a geographic atlas, historical calendars, a daily fire-observation replay, and focused research/evidence workflows.

## End goal

Return a complete set of cohesive, visually polished standalone HTML pages in which a visitor can understand the project immediately and a scientist can choose a study, inspect dated satellite observations, compare sources and judge data completeness with little effort. Preserve the project's existing functionality and scientific meaning. The current pages are the baseline; improve their presentation and usability using the supplied source and screenshots.

You have the entire offline UI reference. Assume you have no access to the original website, research database, NASA services, credentials or datasets. Open `HANDOFF_START.html`, then inspect each HTML page. Every page contains this brief, its behavior guide, all styling and controllers, and its dummy responses. Each file can be copied and opened independently. The earlier `Replay_UI_Polish_Handoff.html` is not this package's visual baseline.

## What the project portrays

MODIS and VIIRS report thermal detections at different native resolutions. FireAtlas retains their source identities and places eligible observations onto a shared 1 km equal-area grid. A repeated detection in the same cell and UTC date contributes once to that cell-day count. Calendar comparisons and source overlap help users inspect differences between the records.

Historical replay changes the selected observation day and places a concentration heatmap over landscape context. It shows where samples were reported over time. It does not establish a fire perimeter, continuous spread, burned area, ignition time or a forecast. NDVI, terrain, land cover and burn-date layers have their own dates and interpretation limits.

All observation records and analytical figures in this offline package are dummy fixtures. Named study labels and product explanations retain the live page copy; landscape imagery is existing visual context. Never turn dummy values into claims about a real incident or project validation.

## Work through every page

1. **Overview / `index.html`:** preserve the globe-led hero composition, globe container, historical wildfire controls, satellite signals, location/evidence controls and summary/destination sections. Improve clarity, spacing and hierarchy around the globe. Preserve the production globe and every existing satellite/orbit layer when the work is integrated. The frozen offline globe is an asset reference, not permission to replace the real renderer with a static image.
2. **Atlas / `atlas.html`:** make the map, context legend, timeline and study controls easy to read as one workflow. Preserve monthly bars, daily calendar, harmonization bridge, daily source evidence and historical heat grid. Distinguish complete zero detections from partial counts and unknown dates. Keep the NDVI default and visibly unavailable weather option. Make calendar navigation and selected-day details obvious.
3. **Replay / `replay.html`:** center the case → sensor/metric → context → date workflow around the heatmap. Preserve source counts, data status, inspection and exports. Keep UTC date and playback state prominent. Explain density, persistence and FRP separately. A concentration heatmap is not temperature; FRP is reported power in MW. The live 3D surface and the offline reference are distinct capabilities.
4. **Research overview / `research.html`:** simplify study configuration and emphasize Run analysis, three headline values, overlap chart and daily table. Give the focused lab pages a clear entry. Fix the existing mobile overflow without removing information or shrinking all text.
5. **Candidates / `research-candidates.html`:** keep the map/list/detail relationship clear. Preserve sort options, date ranges, detected days, cell-days, raw pixels and source sensors. Represent identity with labels and selection outlines. Candidate groups are connected samples, not confirmed incidents. Retain the accessible table fallback.
6. **Exposure / `research-exposure.html`:** present the three-step workflow clearly. Show unavailable, synthetic, unvalidated and validated status explicitly. Keep the denominator beside each percentage. Distinguish the provided dummy upload from real mask validation. Do not infer coverage from FIRMS detections alone.
7. **Validation / `research-validation.html`:** make evidence gates readable, with plain available/partial/unavailable/external-evidence states. Keep demonstrated calculations separate from claims that require independent labels or review. Preserve all evidence, method and review actions.
8. **Data / `data.html`:** organize source catalog, connection state, imports, pilot cards, archive coverage and native inventory into a coherent readable page. Improve long ledgers with disclosures or useful section hierarchy. Keep NASA FIRMS and NOAA HMS source identity distinct. Import and sync remain production-service actions, not decorative success buttons.
9. **Method / `method.html`:** retain the five-stage flow, actual record-to-cell trace interface, evidence scenes, dated timeline, source disclosures and calibration charts/table. Make methodology understandable in progressive detail. Preserve units, grid explanation, provenance and caveats.
10. **Review / `review.html`:** retain the 30-sample workflow, immutable identifiers, expected values, independently entered reviewer observations, progress and exports. Make it easy to move between samples and identify incomplete entries. Do not auto-fill human observations from expected fields.

## Shared design direction

- Preserve the dark observatory identity and use a coherent restrained visual system.
- Build a deliberate type scale, spacing system, consistent surfaces and clear emphasis for primary actions.
- Keep maps and charts visually anchored to their legends and interpretation notes.
- Use semantic source colors consistently: MODIS amber, VIIRS cyan, shared cells muted green, unknown/incomplete gray with a pattern or dashed boundary. Heat magnitude uses a continuous ramp. Where the current page uses other colors, propose and apply an intentional shared system across all affected pages.
- Pair colors with text, symbols or patterns. Selection is an outline/state, not another sensor color.
- Reduce competing notices through hierarchy and disclosure while preserving the scientific limitations where the user needs them.
- Keep tables usable through horizontal scrolling where needed; the page itself should not overflow on mobile.
- Keep navigation and study-context handoff consistent across pages. Preserve the flat routes.
- Use the supplied local fonts and assets or local replacements with an explicit license. Do not introduce remote fonts, imagery, APIs or accounts into the offline deliverable.

## Implementation boundaries

Preserve all IDs used by the page controllers, labels, input names, `data-*` attributes and accessibility relationships. Restructuring surrounding markup and classes is allowed if controls and controller contracts continue working. Preserve scientific API response schemas and calculation units. Do not rewrite calculations to simplify a visual design.

Each HTML is the complete editable implementation. Inline style/script blocks have data-source-file labels indicating their original role. The inline offline adapter, embedded dummy library, and capture-based Earth adapter exist only to make this handoff usable. Do not promote them into the real application's data path. Explain any controller changes needed for your layout separately from styling changes.

Retain the synthetic notice in the offline pages. Do not mislabel a dummy service result, mask rate, review submission or evidence export as an actual validated result. Additional fictional UI examples must be identified as such.

## Completion criteria

- All ten pages are redesigned and form one consistent visual system.
- The existing globe-led introduction, source controls and evidence workflows remain represented.
- Maps, heatmap, calendars, history grid, overlap chart, calibration visuals and review samples remain populated with the supplied dummy states.
- Case, sensor, metric, date, playback, candidate sorting/selection, disclosures, mask-demo upload and local exports still work within the offline fixture scope.
- Selected/hover/focus, empty, partial, unavailable and populated states are understandable.
- Layouts are usable at approximately 1440, 1024 and 390 px, with readable text and reachable controls.
- Keyboard users can navigate forms, select dates/candidates, open dialogs and read a table alternative to map information. Preserve screen-reader labels and reduced-motion behavior.
- No external network connection is needed to open the deliverable.
- Return one complete standalone HTML per page and a concise integration note identifying changed files, preserved hooks and fixture-only behavior.

Continue working page by page until those criteria are met. Deliver the actual edited standalone HTML files with CSS, JavaScript, and assets embedded, not just screenshots, isolated mockups or a visual recommendation list.

## Study context

`lab.js` preserves `year`, `month`, `bbox`, `as_of`, `series`, `day`, `distance_km`, `gap_days`, `region`, and `layer`. Keep `data-context-link`, `data-context-field` and navigation `data-page-link` attributes. Mask files are not placed in URLs or carried automatically to another page.

## Fixture meaning

- Density: concentration of reported shared-grid samples, not fire temperature.
- Persistence: distinct observed dates through the selected frame, not continuous burning duration.
- FRP: satellite-reported fire radiative power in MW, not burned area.
- Complete export: completeness of a requested export window; it does not prove pass/cloud coverage.
- Partial count: positive rows exist but the requested export is not complete.
- Unknown: missing evidence; never silently display as zero fire activity.
- Shared cell: sources occupy the same grid cell and UTC day; do not add raw sensor counts to compute the union.
- Candidate group: connected detection samples; incident membership is unconfirmed.
- Coverage rate: detected-in-mask cell-days / observed mask cell-days × 100, with source and mask status shown.

## Additional review states

Download the embedded synthetic coverage mask from the designer brief and upload it on Exposure to see both synthetic denominator cards. Select a harmonized calendar day to reveal dated dummy rows. Change replay metric and sensor view to inspect legend/table changes. Open candidate detail and method evidence disclosures. Fill review fields to inspect progress without claiming a real review.

The streamed Earth and 3D elevation are offline captures. Preserve the original production renderer when integrating visual changes. This file includes a frozen visual reference, not a replacement for the live renderer.
